**系统管理员操作手册：管理接入、账号与平台运行**

你可以管理全平台组织与账号，查看全部人员的使用分析及会话详情，并处理采集和数据运行问题。系统管理员自己的采集和使用记录仍从“我的空间”查看。


### 一、组织分析：检查推广进度与使用情况

进入“组织分析”，在侧栏选择 全部一级部门或具体部门。查看注册、待采纳、已采纳及累计采纳率，再结合所选期间的使用数据判断实际活跃情况。

从待采纳人数进入成员名单，协助员工完成注册后的安装步骤。人员没有上报不能直接判定为未使用 Trae；应先核对是否安装、凭据是否有效及最近上报。停用/删除账号单独展示，仍保留在累计采纳统计中。

### 二、组织管理：部门、成员与账号

新系统的超级管理员可先进入工作区创建部门。管理员本人领取采集凭据前，也需在“采集安装”按提示完成注册。为预建档员工签发临时密码后，指导其登录、改密并完成注册；不需要发送邮箱验证码。

进入“组织管理”查看全部部门成员，或切换到某个一级部门。部门配置用于新增、修改和维护部门；成员维护用于录入、导入、关联已有身份及调整组织归属。部门调动不将历史使用重新划给当前部门。

成员导入按页面提供的模板填写，先上传预览并处理错误再提交；只使用本版本仍支持的字段，不能再通过导入选择是否纳入统计。

在成员“更多”中进行角色与管理范围授权、临时密码发放/重置、邮箱更正、停用、恢复和逻辑删除。先核对目标人员和操作影响，再填写必要原因并确认。配置管理的固定管理员按页面说明由部署负责人维护。

停用会停止平台登录及该账号新增 Hook/插件采集，但保留历史；逻辑删除还结束管理授权。恢复账号不恢复已撤销的安装凭据，逻辑删除后的管理权限也不会自动重新授予。

关注停用人数及名单，按原因、开始时间和持续天数复核是否仍需停用；有权限时从名单进入恢复操作。逻辑删除单列，不能当作所有人都应尽快恢复的临时状态。平台没有人工统计排除开关。

### 三、采集安装管理：查看接入状态

在目标成员“更多 → 采集安装管理”核对姓名、邮箱、Hook 凭据状态和最近成功上报。该视图只读，不展示他人 API 码；不能代领个人安装材料。本人网页“采集安装”展示共用插件 API 码与来源，实际安装和修复由本人在 Trae 插件完成。

指导员工在插件登录、完成全局 Hooks 启用并产生正常对话，再核对成功保存证据。文件就绪、来源已登记和采纳是不同状态。账号或凭据异常时按实际错误处理，不通过反复下载或覆盖本地配置尝试恢复。

### 四、Token 使用分析：查看全员会话

进入“组织分析”，在左侧选择“Token使用分析”，选取部门和时间范围，在列表中打开具体会话。结合执行轨迹、用量与出账、原始事件和会话信息查看证据；不要把一次 Hook 或工具调用直接当成一次模型调用。

官方用量、本地估算和计费用量模拟分别理解：缺失官方数据不是零费用，模拟结果也不是最终账单。需要查看本人数据时，使用“我的空间”的个人入口。

### 五、代码流向追踪

进入“组织分析”，在左侧选择“代码流向追踪”。按当前部门人员、项目路径、仓库地址或人员查询，不按日期过滤。用来源标签区分 Hook 与插件；项目按已认证人员、来源、采集端及规范化目录区分，显示 Git 远端、分类和观测时间。Hook 的“关联会话”可打开仍在近期窗口内的详情，插件提供观测历史。

通过“部门仓库白名单”维护精确主机或完整仓库规则。个人／部门标签不表示项目属于哪个具体部门，也不证明已推送代码。探测失败保留有效旧配置并明确提示；空清单可能尚无支持项目观测的新版采集器上报，不能认定未使用Trae。对话里出现的URL不作为Git配置观测。

### 六、系统运营

“采集健康”用于查看近期采集、工作进程和任务状态；“出账同步”用于查看官方用量同步的覆盖、成功与失败；“数据保留”用于查看保留维护及存储观测。先确认页面时间与数据是否新鲜，再判断是否需要进一步排查。

这些页面中未提供的操作，不写成网页一键修复功能。涉及使用数据清理时，两来源均受人员/期间清理约束；从有权限的成员操作入口预览范围与影响，按页面确认流程执行；数据清理与账号停用不同，不能把删除的数据视为可由恢复账号自动找回。

### 七、我的空间与常见问题

使用个人概览、本人的 Token 使用分析和采集安装维护自己的接入。可用时从“修改密码”维护本人密码；配置管理员按部署管理规则处理。

- 员工已注册但待采纳：核对本机安装、个人凭据及是否有新增上报。
- 多人同时不上报：结合采集健康、账号状态和部署地址排查。
- Hook 正常但官方用量缺失：查看出账同步的覆盖和错误，不能把它当成 Hook 安装失败。
- 已恢复账号仍不能上报：检查安装是否被单独撤销，随后触发新事件并刷新。
